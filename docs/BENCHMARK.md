Фактический локальный запуск выполнен 2 ноября 2026 года (Москва; в JSON UTC —
1 ноября 23:08). Исходные измерения: [benchmark-windows.json](benchmark-windows.json).

Оборудование: Intel Core i5-13420H, 12 логических процессоров; Windows 11 AMD64.
Компилятор: Zig 0.17.0 `cc`, C17, `-O2`, строгие предупреждения как ошибки.
Python 3.12.14 запускает процесс и измеряет его; Python не участвует в анализе C.

## Повторение

```bash
python scripts/build.py --cc gcc
python scripts/benchmark.py --binary build/logscope --sizes 10000,100000,1000000 --repeats 3 --compiler-description "GCC: укажите версию; C17 -O2" --output build/benchmark.json
```

Для фактически опубликованного запуска использован `zig cc` на Windows;
полная строка компилятора и флаги находятся в исходном JSON.

Параметры: seed 2026, 10 000 возможных товарных путей, ёмкость top 128,
окно 120 минут. Синтетический файл моделирует 90 минут с редкими запоздавшими
событиями и всплеском ошибок оплаты. Для каждого размера — один прогрев и три
измерения. Во время замера чтение идёт из файла; генерация и создание отчёта HTML
не включены. Измеряются запуск процесса, чтение, C-анализ и запись JSON.

После каждого запуска проверяются точные запросы, 5xx, байты и сумма задержек.
При несовпадении измеритель прекращает работу, не публикуя успешный результат.
Windows PeakWorkingSetSize и Unix `wait4().ru_maxrss` относятся к отдельному
дочернему процессу. На macOS ru_maxrss задан в байтах, на Linux — в КиБ; скрипт
нормализует единицы. Память генератора Python в эту метрику не входит.

## Ограничения интерпретации

Файловый кэш прогрет; холодный диск, сеть и параллельная обработка не измеряются.
Компьютер не выделен исключительно под тест и фоновые задачи могли повлиять
на длительности. Отсюда полезность сырых повторов и медианы. Это измерение одного
окружения, не сравнение компиляторов и не обещание пропускной способности.

Почти неизменная память согласуется с O(capacity + window). Чтобы проверить
зависимость от числа различных ключей, повторите с `--cardinality 1000000`;
чтобы изучить цену точности — с `--capacity 4096`. Новые результаты не следует
смешивать с таблицей выше без сохранения параметров и окружения.

Текущие локальные числа относятся к сборке до последующего перевода комментариев
и поясняющего текста; алгоритмы измеренного ядра не менялись. Для точного
сопоставления используйте SHA256 из исходного JSON или повторите замер.
