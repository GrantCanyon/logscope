# План эксперимента точности и памяти Space-Saving

Навыки: writing-plans и executing-plans; реализация по шагам, без новых субагентов.
Контракт утверждён ведущим агентом 2 ноября 2026 года; независимую матрицу проверяет QA.

**Цель:** измерить инженерный компромисс между ёмкостью, точностью частот/top-k,
временем и памятью на одном и том же потоке. Основной CLI и C-алгоритмы не меняются.
**Архитектура:** отдельный Python-эксперимент создаёт TSV, читает его точным Counter,
запускает имеющийся CLI, проверяет гарантии и сохраняет JSON + автономный русский HTML.
**Технологии:** Python 3.10+, только стандартная библиотека; C-процесс измеряется
существующим `benchmark.run_process` (Windows PeakWorkingSetSize / Unix wait4).

## Контракт

- Для каждой пары requested_cardinality/seed создаётся один файл. Все capacity
  получают идентичные байты и SHA256; фактическое D определяет Counter.
- Две независимые серии: все запросы и только 5xx; ключ — метод + target без query.
- CLI запускается с `--capacity C --top C --json`. Проверяются уникальность ключей,
  все tracked-интервалы `lower <= truth <= upper`, `lower=upper-error`,
  сумма upper = объёму серии. Для неприсутствующих ключей при полном sketch:
  truth <= минимальному upper. При D<=C обязаны присутствовать все ключи с точными
  границами. Пустая серия корректна, у неё нет границ и recall равен null.
- Для top-k: k_eff=min(k,D), tau — частота k_eff-го ключа эталона;
  H — ключи с частотой >tau, E — с частотой =tau, R — первые min(k,C) ключей CLI.
  h=|R∩H|, e=|R∩E|, s=k_eff-|H|. Recall lower=(h+max(0,e-(|E|-s)))/k_eff;
  upper=(h+min(e,s))/k_eff. Это диапазон по допустимому разрешению ничьей,
  не доверительный интервал. Upper — оптимистический tie-aware recall.
  При C<k знаменатель не уменьшается до C.
- Метрики частот: средняя и максимальная ширина tracked-интервалов; количество
  нарушений всех перечисленных гарантий должно быть нулевым. Нарушение делает
  эксперимент неуспешным и не маскируется усреднением.
- Время и RSS относятся только к отдельному C-процессу, включая запуск/чтение/JSON;
  Python-генератор и Counter исключены. Один прогрев и три измерения; capacity
  обходятся в детерминированно перемешанном порядке по раундам.
  Ни монотонность времени/RSS/recall, ни холодный файловый кэш не обещаются.
- Размер по умолчанию: 100000 строк, seed=2026, k=10,
  requested_cardinality=32,256,4096; capacity=16,64,256,1024. Это 12 точек,
  а не длительный перебор. Все данные синтетические.
- JSON `experiment_schema_version=1`: environment, parameters, datasets;
  dataset содержит seed, requested_cardinality, actual distinct counts,
  input_sha256, input_bytes и результаты по capacity (метрики двух серий,
  все временные/RSS отсчёты и медианы). Время замера и окружение не обязаны
  совпадать при повторении; входной hash и метрики точности — обязаны.
- HTML автономный, русский, без JS/внешних ресурсов; диаграммы и таблицы
  показывают наблюдаемые значения и диапазоны при ничьей без подгонки.

## Фокус независимого ревью

Ничьи на границе k не превращаются в произвольный штраф или ложные 100%; C<k
сохраняет denominator; ошибки 5xx могут отсутствовать; D не подменяется заданным
числом путей; память Counter не попадает в RSS C. Для каждого условия есть fixture
или subprocess-проверка выше. Дополнительные зависимости и новые функции CLI
не входят в этот этап.

Решение по фиксации: метрики и HTML сохранены одним общим проверенным коммитом
после полного сквозного цикла; промежуточная версия метрик отдельно не публиковалась.
