Как читать результат

Границы показателя совпадения — диапазон возможного совпадения с точным top-k при допустимом разрешении равных частот, не доверительный интервал. Верхняя граница оптимистическая. Широкий диапазон при одинаковых частотах сам по себе не означает ошибку оценки частот.

Ширина частотного интервала — upper − lower в числе запросов. Доля «Точных частот среди отслеживаемых» относится только к отслеживаемым ключам, а не ко всем ключам входа. При достаточной ёмкости все частоты должны быть точными.

Все проверенные интервалы и границы пропущенных ключей соблюдены. Суммы upper сверены с объёмами независимых потоков.

Методика и ограничения

Для каждой кардинальности использован один файл с фиксированным seed=2 026. Фактическое число ключей D определено по файлу. Ёмкость меньше k не уменьшает знаменатель: k_effective=min(k,D). Для пустого потока показатель совпадения не определён и показан прочерк.

отдельный C-процесс: запуск, чтение, анализ и JSON; прогретый кэш. Генерация, Counter, проверка метрик и HTML находятся вне измеряемого времени. пик RSS только C-процесса; Python Counter и генератор исключены. Память C включает базовую стоимость процесса и библиотек.

Порядок ёмкостей детерминированно перемешан по раундам. Время, пиковая память и совпадение с top-k не обязаны монотонно изменяться в каждом наборе. Кэш прогрет; холодный диск, сеть и параллельная нагрузка не измеряются. Результат одного окружения не является обещанием производительности.
